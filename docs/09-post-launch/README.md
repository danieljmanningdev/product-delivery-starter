# Post-Launch

Post-launch work verifies that the product continues to behave correctly after release and turns real usage, feedback and operational data into informed improvements.

## Objectives

- Monitor launch health
- Respond to production issues
- Review real user behaviour and feedback
- Review search/performance data where applicable
- Maintain security and dependencies
- Convert evidence into prioritised improvements

## Inputs

- Production deployment
- Monitoring/logs
- Analytics where used
- Search Console where used
- User/client feedback
- Support requests and defects

## Outputs

- Post-launch review
- Prioritised backlog
- Maintenance actions
- Lessons learned
- Updated documentation

## Principles

Do not optimise metrics merely because they are measurable. Prefer evidence connected to user or business outcomes.

Separate defects from enhancements so launch problems are not hidden inside a general backlog.

Feed useful lessons back into this starter so future projects benefit from them.

## Exit Criteria

A project can move into normal maintenance when:

- [ ] Launch-critical issues are resolved
- [ ] Monitoring shows stable operation
- [ ] Initial feedback has been reviewed
- [ ] Performance/search data has been reviewed where applicable
- [ ] Improvement backlog is prioritised
- [ ] Documentation/handover is complete
- [ ] Ongoing ownership is clear
