# Design

The Design stage turns validated UX structure into a coherent, accessible visual system and high-fidelity interface.

## Objectives

- Establish design foundations
- Create reusable design tokens
- Define typography and colour systems
- Define spacing, sizing, radius and layout rules
- Build reusable components and variants
- Produce responsive high-fidelity screens
- Prototype important interactions
- Document design decisions for implementation

## Inputs

- Product requirements
- UX flows and screen specifications
- Wireframes
- Brand assets and guidelines

## Suggested Structure

- `foundations.md` — colour, typography, spacing, sizing and layout
- `components.md` — reusable component inventory and state coverage
- `prototype.md` — prototype scope and validation notes
- Figma file/link — source of truth for visual design where applicable

## Principles

Prefer systems over isolated values. Components should consume semantic tokens rather than hard-coded visual values where practical.

Accessibility is a design input, not a final visual check.

Design responsive behaviour rather than only fixed desktop and mobile snapshots.

## Exit Criteria

Move to Development when:

- [ ] Design foundations are documented
- [ ] Primitive and semantic colour tokens are defined
- [ ] Typography hierarchy is defined
- [ ] Spacing and sizing systems are defined
- [ ] Required components exist
- [ ] Interactive component states are designed
- [ ] Important responsive behaviour is defined
- [ ] Critical screens and states are designed
- [ ] Primary flows are prototyped where useful
- [ ] Accessibility has been reviewed
- [ ] Design has been approved where approval is required
