# UX

The UX stage defines how users understand, navigate and complete tasks within the product before visual polish or implementation dominates decisions.

## Objectives

- Define information architecture
- Map important user journeys and flows
- Define screens and states
- Create low-fidelity wireframes
- Identify reusable interface components
- Validate navigation and interaction models
- Account for errors, empty states and recovery paths

## Inputs

- Client brief
- Discovery findings
- Product requirements

## Structure

- `definitions/` — shared UX terminology and domain concepts
- `flows/` — user journeys and task flows
- `screens/` — screen/page specifications
- `components/` — UX-level component specifications
- `schemas/` — optional schemas for structured UX documentation
- `wireframes/` — links, exports or notes for low-fidelity designs

## Principles

Solve structure and behaviour before visual decoration.

Design complete experiences rather than only the happy path. Consider loading, empty, error, success, permission and destructive-action states where applicable.

Important user actions should have clear feedback and recovery paths.

## Exit Criteria

Move to Design when:

- [ ] Information architecture is defined
- [ ] Primary user journeys are mapped
- [ ] Critical user flows are documented
- [ ] Required screens/pages are identified
- [ ] Navigation is understood
- [ ] Wireframes exist for important experiences
- [ ] Empty/error/loading/success states have been considered
- [ ] Accessibility implications have been considered
- [ ] Major UX questions have been resolved or recorded
