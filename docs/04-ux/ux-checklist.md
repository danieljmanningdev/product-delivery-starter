# UX Checklist

## Information Architecture

- [ ] Content inventory reviewed where applicable
- [ ] Sitemap / application hierarchy defined
- [ ] Navigation model defined
- [ ] Labels use language users can understand
- [ ] Important destinations are easy to reach
- [ ] Relationships between content are clear

## User Journeys

- [ ] Primary user groups identified
- [ ] Primary journeys mapped
- [ ] Entry points considered
- [ ] User goals identified
- [ ] Exit/success points identified
- [ ] Friction and failure points considered

## User Flows

For each critical task:

- [ ] Entry condition defined
- [ ] Steps defined
- [ ] Decisions/branches defined
- [ ] Validation failures considered
- [ ] Permission failures considered where relevant
- [ ] Cancellation/recovery considered
- [ ] Success outcome defined

## Screens

- [ ] Every required screen/page has a purpose
- [ ] Primary action is clear
- [ ] Secondary actions are appropriately prioritised
- [ ] Content hierarchy is clear
- [ ] Navigation context is clear
- [ ] Destructive actions require appropriate safeguards

## States

Consider where applicable:

- [ ] Default
- [ ] Loading
- [ ] Empty
- [ ] Success
- [ ] Error
- [ ] Validation error
- [ ] Disabled
- [ ] Offline / unavailable
- [ ] Permission denied
- [ ] Not found

## Forms

- [ ] Only necessary information is requested
- [ ] Labels are explicit
- [ ] Required/optional fields are understandable
- [ ] Validation timing is appropriate
- [ ] Errors explain how to recover
- [ ] Entered data is preserved after recoverable errors where practical
- [ ] Success feedback is clear

## Accessibility

- [ ] Interaction does not depend solely on colour
- [ ] Keyboard interaction is considered
- [ ] Focus order is logical
- [ ] Focus visibility is planned
- [ ] Accessible names/labels are considered
- [ ] Content order remains meaningful responsively
- [ ] Zoom/reflow implications are considered
- [ ] Motion is not essential to understanding

## Wireframes

- [ ] Primary desktop layouts exist where required
- [ ] Primary mobile layouts exist where required
- [ ] Realistic content lengths are considered
- [ ] Important states are represented
- [ ] Layout decisions map back to requirements

## Validation

- [ ] Primary flow can be explained without relying on visual styling
- [ ] Critical requirements are represented in UX
- [ ] Unresolved assumptions are recorded
- [ ] Stakeholder/user feedback is incorporated where available
