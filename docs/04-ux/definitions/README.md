# UX Definitions

Use this directory for shared product and UX terminology that needs a precise meaning across requirements, flows, screens, design and implementation.

Definitions are useful when a term could otherwise mean different things to different people.

## Example

```markdown
# Project

A user-owned collection of related work items.

## Rules

- A project has one owner.
- A project can be archived.
- An archived project remains readable but cannot accept new work items.

## Related

- Requirements: FR-012, FR-013
- Screens: SCR-PROJECT, SCR-PROJECT-EDIT
```

## Guidelines

- Define domain concepts, not ordinary words.
- Record behavioural rules when they affect UX.
- Link definitions to requirements/screens where useful.
- Keep terminology consistent with interface copy.
- Update definitions when product rules change.
