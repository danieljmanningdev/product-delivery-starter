# Product Delivery Checklist

This is the quick operational view of the full delivery process. Detailed guidance and templates live under [`docs/`](docs/).

Mark irrelevant items **N/A** rather than silently skipping them.

## 01 — Brief

- [ ] Project overview captured
- [ ] Problem described
- [ ] Business goals captured
- [ ] Target users identified
- [ ] Primary action/outcome identified
- [ ] Initial scope defined
- [ ] Existing assets recorded
- [ ] Constraints recorded
- [ ] Success criteria recorded
- [ ] Open questions recorded

## 02 — Discovery

- [ ] Business/product context understood
- [ ] Problem evidence reviewed
- [ ] User goals/problems investigated
- [ ] Existing product/system reviewed where applicable
- [ ] Competitors/alternatives reviewed where useful
- [ ] Content/brand/technical context reviewed
- [ ] Accessibility needs considered
- [ ] Security/privacy/compliance context considered
- [ ] Assumptions recorded
- [ ] Risks and opportunities recorded

## 03 — Requirements

- [ ] Functional requirements defined
- [ ] Non-functional requirements defined
- [ ] Requirements prioritised
- [ ] Critical acceptance criteria defined
- [ ] Accessibility requirements defined
- [ ] Performance requirements defined where useful
- [ ] Browser/device expectations defined
- [ ] Security/privacy requirements defined
- [ ] SEO/discoverability requirements defined where applicable
- [ ] Dependencies and constraints recorded
- [ ] Out-of-scope items explicit

## 04 — UX

- [ ] Information architecture defined
- [ ] Navigation model defined
- [ ] Primary journeys mapped
- [ ] Critical flows documented
- [ ] Screens/pages identified
- [ ] Primary/secondary actions defined
- [ ] Empty/loading/error/success states considered
- [ ] Form behaviour considered
- [ ] Responsive behaviour considered
- [ ] Accessibility implications considered
- [ ] Wireframes completed where useful

## 05 — Design + Prototype

- [ ] Brand palette established
- [ ] Colour system/contrast documented
- [ ] Primitive colour tokens defined
- [ ] Semantic colour tokens defined
- [ ] Typography scale/hierarchy defined
- [ ] Spacing scale defined
- [ ] Sizing/control scale defined
- [ ] Radius/border/elevation rules defined where applicable
- [ ] Grid/layout rules defined
- [ ] Required components created
- [ ] Interactive states designed
- [ ] Mobile and desktop designs completed
- [ ] Intermediate responsive behaviour considered
- [ ] Critical flows prototyped where useful
- [ ] Accessibility review completed
- [ ] Design approval recorded where required

## 06 — Development

- [ ] Architecture documented
- [ ] Technology choices justified
- [ ] Data model/routes/interfaces defined where applicable
- [ ] Design tokens mapped into implementation
- [ ] Required functionality implemented
- [ ] Responsive behaviour implemented
- [ ] Validation/error handling implemented
- [ ] Accessibility behaviour implemented
- [ ] Security/privacy requirements implemented
- [ ] Performance strategy implemented
- [ ] SEO/metadata implemented where applicable
- [ ] Tests implemented where they improve confidence
- [ ] Logging/observability implemented where required

## 07 — QA

- [ ] Acceptance criteria pass
- [ ] Critical journeys pass
- [ ] Design fidelity reviewed
- [ ] Mobile/tablet/desktop behaviour reviewed as applicable
- [ ] Keyboard-only testing completed
- [ ] Focus behaviour reviewed
- [ ] Screen-reader sanity test completed for critical flows
- [ ] Zoom/reflow checked
- [ ] Contrast checked
- [ ] Automated accessibility scan reviewed
- [ ] HTML/semantic structure reviewed
- [ ] Supported browser compatibility checked
- [ ] Lighthouse/PageSpeed reviewed where applicable
- [ ] SEO/indexing configuration checked
- [ ] Security controls checked
- [ ] Privacy/analytics behaviour checked
- [ ] Final regression completed

## 08 — Production

- [ ] Production configuration ready
- [ ] Secrets/environment variables configured
- [ ] Database migrations/backups reviewed where applicable
- [ ] Domain/DNS/HTTPS ready
- [ ] Logging/monitoring ready where required
- [ ] Rollback/recovery approach understood
- [ ] Deployment succeeds
- [ ] Critical production smoke tests pass
- [ ] Security headers/cookies verified
- [ ] robots.txt/sitemap/canonical/structured data verified where applicable
- [ ] Production performance sanity check completed
- [ ] Analytics/consent verified where applicable
- [ ] Known issues documented

## 09 — Post-Launch

- [ ] Launch health monitored
- [ ] Production errors reviewed
- [ ] User/client feedback reviewed
- [ ] Success criteria revisited
- [ ] Search/analytics data reviewed where applicable
- [ ] Performance reviewed
- [ ] Accessibility issues from real use reviewed
- [ ] Maintenance ownership clear
- [ ] Defects separated from enhancements
- [ ] Improvement backlog prioritised
- [ ] Lessons learned documented
- [ ] Reusable process improvements fed back into this starter
