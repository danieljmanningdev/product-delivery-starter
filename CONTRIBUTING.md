# Contributing

This repository is both a reusable project starter and a living delivery process. Contributions should make future projects clearer, safer or easier to deliver without turning the process into unnecessary bureaucracy.

## Principles

- Prefer reusable guidance over project-specific rules.
- Keep the process proportional to project risk and complexity.
- Mark checks as N/A when they do not apply rather than removing useful safeguards globally.
- Prefer authoritative accessibility, security and platform guidance where requirements matter.
- Avoid adding tools solely because they produce another score.
- Explain why a new process step is useful.

## Changes to the Delivery Process

When changing a stage, consider whether related templates/checklists also need updating. For example, a new requirement category may affect UX, development, QA and launch documentation.

## Pull Requests

Use the repository pull request template. Keep changes focused and describe:

- the problem being solved
- why the change belongs in the reusable starter
- which stages are affected
- how the change was validated

## Documentation Style

- Use clear, direct language.
- Prefer checklists for repeatable verification and prose for principles/explanation.
- Avoid pretending every project needs every technique.
- Distinguish requirements from suggestions.
- Avoid duplicating the same checklist across multiple stages unless each occurrence represents a genuinely different decision point.

## Security and Privacy

Do not include real client secrets, credentials, personal data or confidential project material in examples.
